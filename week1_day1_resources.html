所以资源取舍原则：官方文档当字典查（中文版质量够用）+ 一页速查表映射语法 + 立刻用 mypy 让自己报错。视频课对你 ROI 最低，一律不推荐。Java 只当类比用——看得懂 class 和接口概念就够了，不需要为这条路去补 Java。

类型注解（最该花时间的一块）

约 30 分钟
主推
Python 官方 typing 文档（中文）
别通读。只看 4 处：Optional / Union（现在直接写 T | None）、list[str] / dict[str, int] 泛型、Literal、Protocol。其余当字典备查。
速查
mypy cheat sheet（一页纸）
这张表覆盖你 90% 会用到的语法，建议直接打印或贴在编辑器旁边。比任何教程都高效。
选读
Real Python · Python Type Checking
英文长文，只读 Gradual typing 和 Protocol 两节（约 20 分钟）。Protocol 就是 Python 版的 interface，理解它你就懂为什么 Python 不写 implements。
你熟的（JS / C / Java 皮毛都算）Python 写法
Optional<Device>→Device | None
enum Status→Literal["up", "down"]（运行时就是 str，零开销）
interface Probe→class Probe(Protocol)（结构化，不用显式实现）
Map<String, List<Device>>→dict[str, list[Device]]
泛型 <T>→TypeVar("T")

今天必须做的一个动作

注解不会在运行时自动检查（这点和 Java 完全不同），必须靠静态检查器。装上跑一次，你才会真正记住：

pip install mypy
mypy day1_typing_drill.py

我给你准备了这个钻练文件，里面有 3 处故意写错的类型。目标：修到 Success。我实测会报 4 条：

day1_typing_drill.py:30: error: Missing return statement  [return]
day1_typing_drill.py:32: error: Incompatible return value type (got "str", expected "int")  [return-value]
day1_typing_drill.py:38: error: Argument "status" to "Device" has incompatible type "str"; expected "Literal['up', 'down']"  [arg-type]
day1_typing_drill.py:49: error: Item "None" of "Device | None" has no attribute "cpu"  [union-attr]
Found 4 errors in 1 file (checked 1 source file)

修法有两类：改代码（真返回 int / 加 None 判断）或改注解（把参数类型放宽）。两种都对，但你要能说出为什么选这个——这就是面试里「你懂不懂类型系统」的分水岭。

异常处理（Agent 项目的生死线）

约 20 分钟
主推
官方教程 · 第 8 章 Errors and Exceptions（中文）
就一章，20 分钟读完。这一章务必读完，它是后面所有工具调用、重试、降级逻辑的基础。
规范
Google Python Style Guide
只看 Exceptions 和 Naming 两节。团队协作、代码评审看的就是这套。
必须掌握为什么重要（落到你的 Agent 上）
try / except / else / finallyfinally 里关连接——SNMP 会话、文件句柄泄漏都靠它
raise X from e保留原始异常链。线上排障时没有 from，你只能看到一个毫无信息的外层错误
自定义异常继承 RuntimeError，让调用方能区分「设备离线」和「参数传错」
EAFP 风格Python 偏爱「先做，出错再捕」，而不是「先判断再干」（Java 习惯反过来）
contextlib.suppress替代空 except，至少意图明确

一个反例，记住它一辈子

绝对不要写这种：

# 错误示范：Agent 里这么写，模型永远不知道工具失败了
try:
    result = get_interface_errors(device)
except:
    pass          # 静默吞掉 → 模型拿到 None → 幻觉出一个诊断

正确姿势在 day6_agent_llm.py 的 execute_tool() 里：把异常转成结构化的错误对象喂回模型，模型看到 {"error": "..."} 才知道该换策略。这就是「Agent 能自我修正」的物理基础。

venv / pip（环境隔离）

约 20 分钟
主推
官方 venv 文档（中文）
只看开头「创建虚拟环境」和「激活」两段，后面 API 部分跳过。理解 bin/Scripts 里到底放了什么就行。
选读
Real Python · venv 入门
讲清了「为什么需要隔离」。你熟悉 Maven 的 per-project 依赖，看这篇会有强烈既视感。
2026 现状
uv（新一代包管理器）
现在都市主流了：一条命令替代 venv + pip + pip-tools，速度快 10–100 倍，自带 lock 文件。建议先懂 venv 原理，再用 uv 干活。简历里写「用 uv 管理依赖」是加分项。

必须练会的 6 条命令

python -m venv .venv                        # 建环境（等价新建一个独立 JDK 沙箱）
.venv\Scripts\activate                      # 激活（macOS/Linux: source .venv/bin/activate）
pip install -r requirements.txt             # 按清单装
pip freeze > requirements.txt               # 反向导出（记得去掉无关包）
pip install -e .                             # 本地可编辑安装，改代码不用重装
pip install xxx -i https://pypi.tuna.tsinghua.edu.cn/simple   # 国内加速

项目结构

约 30 分钟
主推
The Hitchhiker's Guide · Structuring Your Project
这一章是这个问题最经典的答案，没有之一。看完你就懂为什么要 src layout、为什么 __init__.py 不能乱放逻辑。
打包
PyPA 官方打包教程
中文页已 404（我验过），用英文版。只有你要「把自己的工具包 pip install 给别人用」时才需要，Day 1 可以先跳过。
选读
Real Python · Modules and Packages
补 import 机制和 __init__.py。你踩过 JS 的模块解析，看这个很快。

直接抄这个结构（Agent 项目通用）

snmp-agent/
├── pyproject.toml            # 依赖 + 工具配置（mypy/ruff 都写这）
├── README.md
├── .env.example              # 配置模板；真 .env 进 .gitignore
├── src/
│   └── agent/
│       ├── __init__.py
│       ├── main.py           # 入口：CLI 或 FastAPI 启动
│       ├── core.py           # ReAct 循环 / 编排
│       ├── llm.py            # 模型客户端（可替换）
│       └── tools/
│           ├── snmp.py       # 采集工具
│           └── registry.py   # 工具注册表（schema + 实现）
└── tests/
    └── test_core.py

两个关键点：① src/ 避免「本地目录遮蔽安装包」的经典坑；② tools/ 独立成目录，将来加 MCP 或换框架时只需改 registry.py。

六个「千万别」，比推荐更重要

  • 别看 40 小时全套视频课。你会 JS/前端、读过 C，编程概念不是零基础，看视频的 ROI 很低——但该动手写的别跳，Python 的坑只有手打才会撞上。
  • 别用 Python 2 教程。看到 print "hi"、u"中文"、dict.has_key() 立刻关掉，这些都是十年前的东西。
  • 别一开始啃《流畅的 Python》。它是好书，但属于第二阶段（3 个月后再读）。现在读会打击信心。
  • 别学 Django / Flask 的目录结构。对你毫无用处，你的战场是 FastAPI + Agent。
  • 别抄「Python 面试 100 题」。你面的不是 Python 岗，是 Agent 应用岗，面试官问的是系统设计。
  • 别跳过 mypy。Agent 项目里「类型写错」= 「工具参数传错」= 线上莫名失败，这是最高频的隐性 bug 来源。
