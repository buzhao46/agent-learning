先把症状说准，才知道补什么

「Python 会基础、不常写脚本」不是语法问题——你缺的不是 for 和 if。真正的卡点通常是这五个，你可以对号入座：

① 每次从空白文件开始
连读个 json、配个日志都要现搜，搜一次 10 分钟，一天搜 5 次，正反馈就断了。
② 一个文件写到 300 行
不知道什么时候该拆模块，拆了又不知道怎么 import 回来。
③ 报错看不懂
只会 print 大法，traceback 一屏红字就慌，说不清是自己的错还是库的错。
④ 只能写「能跑」的代码
不会写「出错也能说清哪里错」的代码——而 Agent 项目全靠这个。
⑤ 完整项目没做过
写过 30 行的练习，没写过 300 行、有参数有日志有测试有 README 的东西。
好消息
这五条全部是「写得少」，不是「学不会」。它们的解法只有一个：连续写 21 天。

所以别再去刷教程了。再看 20 小时视频，第 22 天你还是会从空白文件开始。这条路线是「项目驱动」：每天在已有代码上加一个真实功能，21 天后你手上有一个能讲 20 分钟的完整项目。

核心方法：抄 → 改 → 写（三步，缺一不可）

这是从「看得懂」到「写得出」唯一有效的路径，每天每个任务都按这个走

1
抄：把当天的参考代码手敲一遍（不要复制粘贴）。手敲是为了让手指记住 import json、Path(...).read_text() 这些高频动作。
2
改：改一个参数、加一个分支、换一个字段。这一步最关键——你会在改动中撞上报错，撞一次比看十遍文档记得牢。
3
写：关掉参考，从空白文件重写一遍，允许查语法但禁止抄结构。写不出来就回到第 2 步，再改一次。
4
存：把这次学到的片段追加进 snippets.py（我已经给你建好了，10 个常用片段都在里面）。21 天后这就是你自己的工具箱，也是你「不常写」变「常写」的物理保障。

每天的固定节奏（30–50 分钟，别贪多）

  • 0–5 分钟：回读自己昨天写的代码，只干一件事——找出一处你想改的地方。
  • 5–35 分钟：做当天的任务，按「抄 → 改 → 写」走一遍。
  • 35–45 分钟：跑验收命令，绿了才算完成；红了就先读 traceback 最后一行。
  • 45–50 分钟：git commit -m "day N: ..."，然后把新学的片段存进 snippets.py。

断了一天怎么办？不要补，直接接上。连续性的价值远大于完整性。

怎么判断「我算会写了」——三个可验证的信号

  • 信号 1：不看任何参考，30 分钟内能从零写出「读 json → 处理 → 写 csv」的 60 行脚本。
  • 信号 2：看到一屏 traceback，30 秒内能指着最后一行说出「这是我自己第几行的问题」。
  • 信号 3：能把自己 D21 的项目讲给同事听 20 分钟，讲清模块职责、异常边界、为什么这么拆。

三个都做到，你在面试里就敢说「Python 熟练」，因为你有东西可讲——这比简历上写「精通 Python」有用一百倍。

四个千万别（这次的坑和上次不一样）

  • 别追求「先学完再写」。你已经是「学了很多、写得少」的状态，再学只会更糟。写不动的地方再回去查，这叫按需补课。
  • 别一天做三个任务。30 行写透 > 150 行抄完。任务量是设计过的，跳着做等于没做。
  • 别一直用模拟数据。D8 之后必须碰真的 pysnmp，哪怕连的是自己的电脑或一台旧交换机。真实报错才是老师。
  • 别把「跑通了」当完成。每天都要跑一遍 ruff check + mypy，红着过夜第二天会更难改。
21 天 × 40 分钟 ≈ 14 小时，产出约 800 行代码 + 一个能讲的项目。
这比任何一门「Python 从入门到精通」都短，但比它们有用。
